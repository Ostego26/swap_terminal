# Development tooling for swap_terminal. Not needed to RUN the application.
#
# Split out from swap_terminal/requirements.txt on 2026-09-24 so that a
# deployment does not install a test runner and a linter onto a host that holds
# wallet RPC credentials. Install both on a development machine:
#
#     pip install -r requirements.txt -r requirements-dev.txt
#
# THAT LINE NAMED swap_terminal/requirements.txt UNTIL 2026-11-21, AND FOLLOWING IT
# COULD NOT PASS THIS REPOSITORY'S OWN SHIP GATE. Measured that day, in a clean venv
# built by running exactly the command this file used to print:
#
#     24 failed, 5513 passed, 17 skipped
#     regressed 24   disappeared 329   newly skipped 2   exit 1
#
# There are TWO runtime requirements files and they disagree. The root
# requirements.txt declares 13 packages; swap_terminal/requirements.txt declares 11
# and is missing xrpl-py, PyNaCl and httpx. The 329 vanish because the SOL and XRP
# test modules guard themselves with `pytest.importorskip`, which is the correct
# mechanism and is why nothing errored -- the suite got quietly smaller and exited 0
# at collection. The 24 FAILURES are the half that is not merely smaller: a test
# like test_the_XRP_PAYOUT_BLOCKER_IS_NOT_THE_RESERVE asserts WHY a payout is
# blocked, and with the library absent the reason changes.
#
# THE ROOT FILE IS NAMED HERE BECAUSE IT IS ALSO WHAT EVERY IMAGE INSTALLS. Measured:
# docker-compose.web.yml, docker-compose.icp.yml, docker-compose.grc-desk.yml and
# docker-compose.yml all build with `context: .`, and web.Dockerfile and
# harness.Dockerfile do `COPY requirements.txt ./` -- which resolves to the ROOT file.
# So the old line pointed a developer at a dependency set that nothing in production
# uses, and the two answers drifted without anything failing.
#
# WHY THE THREE WENT MISSING, from swap_terminal/requirements.txt's own header: that
# list was built by "walking the AST of every .py file ... collecting every top-level
# import". Measured 2026-11-21: base58, bech32 and ecdsa are imported at MODULE level
# and are all declared; xrpl, nacl and httpx are imported ONLY inside functions, in
# chains/xrp.py, chains/xrp_submit.py and chains/xrp_signing.py, and none of the three
# is declared there. The imports are function-local on purpose, so a deployment with
# no XRP configured refuses cleanly instead of failing at import -- and that same
# choice made them invisible to the audit that was supposed to find them. A top-level
# walk cannot see a dependency that is deliberately not top-level.
#
# tests/test_declared_dependencies_cover_every_import.py is the check that would have
# caught it: it walks EVERY import at any nesting depth and asserts the file named in
# the command above declares all of them.
#
# STILL TWO FILES, AND THAT IS THE OPERATOR'S CALL (rule 16). Consolidating them
# changes which packages a production host installs, on a host that holds wallet RPC
# credentials, so this change only corrects the documented path and the gate; it does
# not reconcile the lists. swap_terminal/requirements.txt remains missing three
# packages the application imports, and nothing installs it any more except
# swap_terminal/README.md's own `pip install -r requirements.txt`.
#
# These two are what CLAUDE.md rule 12 names as the declared standard, so
# neither is optional for anyone changing code here:
#
#     python3 -m pytest          # the suite must pass before committing
#     python3 -m ruff check .    # the files you TOUCHED must be clean

# The test runner. tests/conftest.py puts swap_terminal/ on sys.path, because
# the application imports its own modules rootlessly (`from config import
# Config`). That is CLAUDE.md rule 10's layout gap, not a pytest setting.
pytest>=8.0,<10.0

# The linter, configured in pyproject.toml. Pinned to a minor range on purpose:
# ruff adds rules between minor versions, and a floating upper bound means a
# checkout that was clean on Monday fails on Tuesday for a reason nobody
# changed. Raise the ceiling deliberately, read what the new rules found, and
# fix it -- rule 19 forbids adding a baseline or a blanket ignore to get green
# again. The ceiling is measured: ruff 0.16.8 is what reports "All checks
# passed" over the 84 files here, and pytest 9.1.1 is what runs the 83 tests.
# A first draft of this file said <0.14 and <9.0, which excluded both.
ruff>=0.6,<0.17

# Parses docker-compose.yml for tests/test_docker_build_context.py, which asserts
# that no build context in this repository can carry key material to the Docker
# daemon. Declared rather than assumed: it was ALREADY INSTALLED here (6.0.1) and
# a test that imports it would have passed silently on this machine and failed on
# a clean checkout -- which is the same undeclared-dependency gap that
# requirements.txt was written on 2026-10-05 to close, arriving in the dev list
# instead. A regex over YAML was the alternative and is the wrong trade: the thing
# being checked is a security invariant, and it should not rest on a pattern that
# breaks when somebody reformats a mapping.
PyYAML>=6.0,<7.0
