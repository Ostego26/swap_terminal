# Runtime dependencies for swap_terminal. NOT a dev list -- requirements-dev.txt
# is that, and ruff/pytest are deliberately absent here.
#
# THIS FILE DID NOT EXIST UNTIL 2026-10-05, AND THAT IS THE FINDING. pyproject.toml
# declares `requires-python = ">=3.11"` and a name and a version, and no
# `[project.dependencies]` at all -- so nothing in this repository stated what the
# application needs in order to run. The only record was whatever happened to be in
# the operator's .venv, which is a record on exactly one machine and vanishes with it.
#
# A container is what forced it out: `pip install` has to be given a list, and there
# was none to give. That is the same shape as CLAUDE.md rule 5's "where does the
# decision live" -- if a reader has to inspect a virtualenv to learn what the system
# depends on, the declaration is in the wrong place.
#
# MEASURED, NOT RECALLED. Every third-party top-level import under swap_terminal/,
# wsgi.py and gunicorn.conf.py was collected by parsing the AST of each file and
# subtracting Python's own stdlib_module_names and this repository's own modules --
# twelve distributions. Each version below is the one installed in the environment
# the test suite passes in, read from importlib.metadata, not chosen.
#
# PINNED WITH ==, because an unpinned list makes the image's dependency set a
# function of the day it was built. On a key-holding system "it worked last week"
# has to mean something.
#
# gunicorn is the one entry NOT read from a measurement: it is not installed in the
# environment this was written in, because the suite never starts a WSGI server.
# gunicorn.conf.py is written against it and wsgi.py is its entry point, so it is a
# real runtime dependency with a declared version rather than an observed one, and
# this comment is here so nobody reads that pin as having been verified the way the
# others were (rule 17).
